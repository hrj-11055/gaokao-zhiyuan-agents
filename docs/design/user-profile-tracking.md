# 用户画像追踪方案设计

> 日期：2026-04-21
> 状态：待评审
> 关联：Phase 3.2 多轮对话流程优化

---

## 一、问题定义

### 现状

当前 Agent 每轮对话只靠 Prompt 里的追问指令"自然追问缺失信息"，实际上只会反复问"省份、分数、选科"三件套。原因：

1. **没有状态追踪** — Prompt 是静态文本，Agent 不知道哪些信息已收集、哪些还没问
2. **追问没有方向** — 缺少"要收集什么"的结构化定义
3. **信息无法持久化** — 用户说过的话只存在于对话上下文中，后续无法结构化调用

### 后果

- 用户画像不完整，建议只能泛泛而谈
- 无法生成有价值的"综合个性特征与院校专业分析报告"
- 用户可能被重复追问同一问题，体验差

---

## 二、目标架构

### 当前 Workflow

```
用户输入 → 知识检索 → LLM → 回复
```

4 个节点，直线流，无变量。

### 目标 Workflow

```
用户输入 ──→ 知识检索 ──→ LLM ──→ 回复
                │
                └──→ 参数提取器 ──→ 变量赋值器
                     (从用户消息       (写入对话变量)
                      提取画像字段)
```

**关键变化：** 在知识检索之后、LLM 之前，新增参数提取器，从用户消息中提取画像字段，写入持久化的对话变量。LLM 的 Prompt 模板中引用这些变量。

### 数据流详解

```
第1轮：
  用户："你好，我想咨询高考志愿"
  → 知识检索：匹配到 KB-1 追问类语料
  → 参数提取器：未提取到任何字段
  → 对话变量：全部为空
  → LLM Prompt 注入："画像完整度：0/10，本轮应优先追问省份和分数"
  → 回复："哪个省的？考了多少分？物理类还是历史类？"

第2轮：
  用户："河北物理类，580分"
  → 知识检索：匹配到 KB-1 志愿填报类语料
  → 参数提取器：提取到 province=河北, subject_type=物理类, score=580
  → 变量赋值器：更新这3个字段
  → 对话变量：province=河北, score=580, subject_type=物理类, 其余为空
  → LLM Prompt 注入："已收集 3/10，本轮应追问家庭经济和职业倾向"
  → 回复："580分在河北物理类，位次大概25000左右...你家经济情况怎么样？
           以后想考研还是直接工作？"

第3轮：
  用户："家里条件一般，爸爸在电力局上班，我想求稳"
  → 参数提取器：family_economy=一般, family_resources=电力系统, career_pref=求稳
  → 变量赋值器：更新这3个字段
  → 对话变量：已收集 6/10
  → LLM Prompt 注入："已收集 6/10，本轮应追问擅长科目和地域偏好"
  → 回复：基于已收集信息给出更精准的建议 + 追问擅长科目

第4轮：
  用户："数学挺好，不太想出省"
  → 参数提取器：strengths=数学, region_pref=省内
  → 变量赋值器：更新这2个字段
  → 对话变量：已收集 8/10
  → 回复：高度个性化的推荐 + 追问风险偏好

...几轮对话后，用户画像基本完整，可触发报告生成
```

## 三、用户画像字段定义

### 必需字段（10个维度）

| # | 字段名 | 类型 | 说明 | 提取规则 | 优先级 |
|---|--------|------|------|---------|--------|
| 1 | `province` | string | 省份 | 用户提到省份名 | P0 首轮必问 |
| 2 | `score` | integer | 高考分数 | 数字+"分" | P0 首轮必问 |
| 3 | `ranking` | integer | 全省位次 | "位次""排名""名" + 数字 | P1 有了更好 |
| 4 | `subject_type` | string | 选科类型 | "物理类"/"历史类"/"理科"/"文科" | P0 首轮必问 |
| 5 | `family_economy` | string | 家庭经济 | "条件一般"/"不太好"/"还行"/"预算充足" | P1 第二轮问 |
| 6 | `family_resources` | string | 家庭资源/行业 | "爸爸在XX上班"/"家里有XX关系" | P1 第二轮问 |
| 7 | `career_pref` | string | 职业倾向 | "求稳"/"想赚钱"/"考研"/"考公"/"出国" | P1 第二轮问 |
| 8 | `region_pref` | string | 地域偏好 | "不想出省"/"想去南方"/"想在广东" | P2 第三轮问 |
| 9 | `strengths` | string | 擅长科目/特点 | "数学好"/"文科强"/"动手能力强" | P2 第三轮问 |
| 10 | `risk_pref` | string | 风险偏好 | "想冲一冲"/"求稳"/"保底" | P2 第三轮问 |

### 扩展字段（可选，后续迭代）

| 字段名 | 说明 |
|--------|------|
| `target_majors` | 感兴趣的专业方向 |
| `target_schools` | 关注的学校 |
| `physical_condition` | 身体条件（色盲等限制） |
| `budget` | 学费预算（万元/年） |

### 对话变量存储格式

```json
{
  "province": "河北",
  "score": 580,
  "ranking": null,
  "subject_type": "物理类",
  "family_economy": "一般",
  "family_resources": "电力系统",
  "career_pref": "求稳",
  "region_pref": "省内",
  "strengths": "数学好",
  "risk_pref": null,
  "_collected": 8,
  "_total": 10
}
```

## 四、Workflow 节点设计

### 节点清单（现有4个 + 新增2个）

```
1. start (用户输入)         [已有]
2. knowledge (知识检索)      [已有]
3. parameter_extractor      [新增] 从用户消息提取画像字段
4. variable_assigner        [新增] 将提取结果写入对话变量
5. llm (LLM)                [已有，需改 Prompt]
6. answer (回复)             [已有]
```

### 连线关系

```
start → knowledge → parameter_extractor → variable_assigner → llm → answer
```

### 节点3：参数提取器 (parameter-extractor)

**用途：** 用 LLM 从用户消息中提取结构化画像字段

**配置：**
- 模型：DeepSeek-Chat（低成本，提取任务不需要推理模型）
- 输入：`sys.query`（用户当前消息）+ `conversation_variables`（已有画像，用于增量更新）
- 提取参数定义：10个字段，每个字段带描述和类型
- 输出：提取到的字段 key-value 对

**Prompt 设计：**
```
从用户消息中提取以下信息，只提取用户明确提到的，不要猜测。

字段列表：
- province: 省份（如"河北""广东"）
- score: 高考分数（整数）
- ranking: 全省位次/排名（整数）
- subject_type: "物理类"或"历史类"
- family_economy: 家庭经济状况（"一般"/"不太好"/"较好"/"好"）
- family_resources: 家庭行业资源（如"电力系统""金融""没有"）
- career_pref: 职业倾向（"求稳"/"高薪"/"考研"/"考公"/"就业"）
- region_pref: 地域偏好（"省内"/"省外"/具体省份或城市）
- strengths: 擅长的科目或个人特点
- risk_pref: 风险偏好（"冲"/"稳"/"保"）

用户消息：{{query}}
```

### 节点4：变量赋值器 (variable-assigner)

**用途：** 将参数提取器的输出写入对话变量

**配置：**
- 对每个画像字段设置一个赋值规则
- 如果提取器输出为空，保留原有值不变（不覆盖）
- 如果提取器输出非空，更新为新值

### 节点5：LLM Prompt 改造

**现有 Prompt 模板需要改造：**

```
你是张雪峰...（风格和规则部分保持不变）

## 当前用户画像
省份：{{#conversation_variables.province#}}
分数：{{#conversation_variables.score#}}
位次：{{#conversation_variables.ranking#}}
选科：{{#conversation_variables.subject_type#}}
家庭经济：{{#conversation_variables.family_economy#}}
家庭资源：{{#conversation_variables.family_resources#}}
职业倾向：{{#conversation_variables.career_pref#}}
地域偏好：{{#conversation_variables.region_pref#}}
擅长科目：{{#conversation_variables.strengths#}}
风险偏好：{{#conversation_variables.risk_pref#}}
已收集：{{#conversation_variables._collected#}}/10

## 追问策略
- 已收集 ≥ 7 个维度：回答以分析推荐为主，可以追问1个缺失项
- 已收集 4-6 个维度：回答后追问 1-2 个缺失项
- 已收集 ≤ 3 个维度：先给简短分析，追问最关键的 2 个缺失项
- 全部收集完成：不再追问，专注给建议
- 每次追问结合上下文自然带出，不要像填表
- 已有信息的不要重复问

## 参考资料
{{#context#}}
```

## 五、与核心产品的衔接

### 综合报告生成

当用户画像收集到 ≥ 8/10 个维度时，系统可以：

1. **API 层判断**：小程序端读取 conversation_variables，检查 `_collected` 字段
2. **触发报告生成**：调用独立的报告生成接口，传入用户画像 + 知识库数据
3. **报告内容**：
   - 考生画像摘要（10个维度的结构化呈现）
   - 冲/稳/保院校推荐（基于分数、位次、省份）
   - 专业方向推荐（基于职业倾向、擅长科目、家庭资源）
   - 风险提示（基于家庭经济、风险偏好）

### 数据流向

```
对话（渐进式收集画像）
    ↓
conversation_variables（持久化存储）
    ↓
小程序读取变量 → 判断完整度 → 触发报告生成
    ↓
报告生成 API（用户画像 + 知识库查询 + 模板渲染）
    ↓
综合个性特征与院校专业分析报告
```

## 六、实施步骤

### Step 1：定义对话变量（Dify Web UI）

在 Chatflow 的"变量"面板中添加 12 个 conversation_variable：
- 10 个画像字段 + `_collected`（计数器）+ `_total`（固定值10）

### Step 2：添加参数提取器节点

- 在 knowledge 节点后添加 parameter-extractor 节点
- 配置 10 个提取参数
- 使用 DeepSeek-Chat 模型（降低成本）

### Step 3：添加变量赋值器节点

- 连接 parameter-extractor 输出 → variable-assigner
- 为每个字段设置赋值逻辑（非空时更新）

### Step 4：改造 LLM Prompt

- 在 Prompt 模板中注入用户画像变量
- 添加基于完整度的追问策略

### Step 5：测试验证

用 20 题标准测试集重新测试，重点关注：
- 画像字段是否正确提取
- 追问是否自然且不重复
- 多轮对话后画像是否完整
- 回答质量是否因画像信息而提升

## 七、风险与备选方案

### 风险1：参数提取器增加延迟和成本

**影响：** 每轮对话多一次 LLM 调用
**缓解：** 使用 DeepSeek-Chat（低成本），提取任务 prompt 很短，延迟约 0.5-1 秒
**备选：** 如果延迟不可接受，改为仅在 LLM 回答中输出结构化 JSON（利用 LLM 的 function calling 能力），由后端解析更新变量

### 风险2：提取准确率

**影响：** 用户说"家里还行"可能被提取为"较好"或"一般"
**缓解：** 提取器 prompt 中加示例，字段定义明确
**备选：** 允许覆盖更新——后续轮次中如果用户澄清，新值覆盖旧值

### 风险3：Dify Chatflow 的节点连线限制

**影响：** 当前是直线流（start→knowledge→llm→answer），新增节点后是否支持并行或分支
**缓解：** Dify v1.13 支持复杂连线，parameter-extractor 可以和 LLM 串联
**备选：** 如果节点连线有问题，退回到"全部放 Prompt"方案——在 Prompt 中定义画像框架，依赖 LLM 的上下文理解能力追踪状态

## 八、如果"全放 Prompt"方案的优化思路

如果对话变量方案实施困难，Prompt 优化方案如下：

**在 Prompt 末尾追加：**

```
## 用户画像收集
你需要渐进式收集以下信息，每轮对话结合回答自然追问 1-2 个未收集的维度：
1. 省份（必须）
2. 分数（必须）
3. 选科类型（必须）
4. 家庭经济状况
5. 父母行业/家庭资源
6. 职业倾向（求稳/高薪/考研/考公）
7. 地域偏好
8. 擅长科目
9. 风险偏好（冲/稳/保）
10. 全省位次（如有）

规则：
- 已经问过且用户回答了的，不要再问
- 追问要自然，融入对话，不要像填问卷
- 信息越多，建议越精准
```

**优点：** 实现简单，不需要改 Workflow
**缺点：** 无持久化，长对话后可能丢失信息，无法结构化输出给报告生成
