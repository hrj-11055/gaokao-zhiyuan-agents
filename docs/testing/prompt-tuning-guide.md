# AI Agent 测试与 Prompt 调优方法论

> 适用项目：张雪峰高考志愿填报助手
> 适用工具：Dify Chatflow / 任何 LLM 应用

---

## 一、测试方法

### 1.1 测试流程

```
设计测试题 → 逐条测试 → 标记问题 → 分类统计 → 输出调优清单
```

### 1.2 测试题设计原则

测试题要覆盖**不同意图**和**不同难度**，不能只测"正常情况"：

| 类型 | 占比 | 目的 | 示例 |
|------|------|------|------|
| 黄金路径 | 40% | 核心功能是否好用 | "河北物理类580分能报什么学校" |
| 追问触发 | 20% | 信息不全时是否追问 | "计算机专业怎么样"（没说省份分数） |
| 知识检索 | 20% | 知识库数据是否被引用 | "武汉大学2024在河北分数线" |
| 边界情况 | 20% | 异常/极端输入如何处理 | "我考了900分"、"复读好不好" |

### 1.3 每道题的评估方法

测完每道题，问自己 **3 个问题**：

**Q1：它做了该做的事吗？**（功能性）
- 该追问的追问了吗？
- 该给具体数据的给了吗？
- 该引用知识库的引用了吗？

**Q2：它没做不该做的事吗？**（安全性）
- 有没有编造数据？
- 有没有给确定性的承诺（"一定能上"）？
- 有没有跑题？

**Q3：回答质量怎么样？**（体验）
- 字数是否合适（200-500字）？
- 风格是否符合人设？
- 是否先给结论再解释？

### 1.4 评分标准

每道题用 3 档评分：

| 档位 | 含义 | 后续动作 |
|------|------|---------|
| ✅ 通过 | 回答准确、风格到位 | 不需要改 |
| ⚠️ 部分通过 | 方向对但有瑕疵 | 记录问题，Prompt 调优时处理 |
| ❌ 不通过 | 回答错误或严重偏离 | 必须修复，优先级最高 |

## 二、问题分类体系

测完之后，把问题归类。不同类型的问题，修改方式完全不同：

### A 类：缺少追问

**表现**：用户没给省份/分数/选科，Agent 直接回答了，没追问。

**修改方向**：强化 Prompt 中的追问指令。

**示例修改**：
```
# 修改前
## 追问策略
你必须知道以下信息才能给出有价值的建议：省份、分数、选科

# 修改后
## 追问策略（严格执行）
当用户的问题缺少以下任一信息时，你必须先追问，不要直接回答：
- 省份：直接问"你是哪个省的考生？"
- 分数/位次：直接问"你考了多少分？知道位次也行"
- 选科：直接问"你是物理类还是历史类？"

只缺少1项信息时，追问那1项后给出初步建议。
缺少2项以上时，只追问最重要的1项，不要一次问多个。
```

### B 类：回答太泛

**表现**：说了一堆"可以考虑一些学校"、"选择适合自己的专业"等废话，没有具体学校名、专业名。

**修改方向**：在 Prompt 中加"具体性约束"。

**示例修改**：

```
## 回答规范（新增）
- 每次推荐必须给出至少 3 个具体学校名或专业名
- 禁止使用"一些学校""某些专业""可以考虑"等模糊表述
- 分数相关的回答必须带年份："根据2024年的数据..."
```

### C 类：编造数据

**表现**：Agent 给出了看起来具体但实际不存在或错误的分数线。

**修改方向**：加强"不确定性声明"指令。

**示例修改**：
```
## 数据引用规则
- 只引用知识库中真实存在的数据，不要推测或估算
- 引用时必须标注年份来源："根据知识库中2024年的数据..."
- 知识库没有数据的，明确说："我手头没有这所学校的最新数据，建议你去学校官网或各省考试院查看"
- 绝对不要说"大概在XX分左右"这种模糊估计
```

### D 类：风格不符

**表现**：回答太客气、太学术、像客服，不像张雪峰的说话风格。

**修改方向**：增加更多风格示例，强化语气。

**示例修改**：
```
## 风格要求
- 用"你"而不是"您"，我们是平等的
- 可以用反问句："你觉得呢？""你受得了吗？"
- 可以用口语："说白了""说白了就是""我跟你说"
- 敢下判断："我建议你别报""这个专业我推荐"
- 禁止使用"非常荣幸""很高兴为您服务"等客服用语
```

### E 类：长度不当

**表现**：回答太短（不到100字）或太长（超过800字）。

**修改方向**：在 Prompt 中加长度约束，同时调整模型参数。

**示例修改**：
```
## 长度控制
- 简单追问（只需要问一个问题）：50-100字
- 标准回答（推荐学校/专业）：200-400字
- 复杂对比（两个学校详细比较）：400-600字
- 超过600字的回答需要分段，用标题和小标题组织
```

同时调整模型参数：`max_tokens: 600`（从1024适当降低）

### F 类：知识库未命中

**表现**：知识库明明有数据，但回答没有引用。

这通常不是 Prompt 问题，而是**知识检索配置**问题：

**排查步骤**：
1. 在 Dify 日志中查看该对话的知识检索结果
2. 如果检索结果为空 → 调整检索参数（Top K 从 3 提到 5，Score 阈值从 0.7 降到 0.5）
3. 如果检索到了但 LLM 没引用 → 在 Prompt 中加强引用指令
4. 如果 economy 模式检索不准 → 升级为 high_quality 模式（需要 embedding 模型）

## 三、Prompt 调优工作流

### 3.1 一次完整的调优周期

```
第1步：测试 20 题，填写报告（1小时）
         ↓
第2步：统计问题分布，按 A-F 分类（15分钟）
         ↓
第3步：只改最集中的 1-2 类问题（30分钟）
         ↓
第4步：用最差的 5 题重新测试（15分钟）
         ↓
第5步：如果改善 → 继续下一类问题
       如果没改善 → 回退修改，换一种改法
```

### 3.2 核心原则

**原则 1：一次只改一类问题**

不要同时改追问策略、回答风格、数据引用——改完你不知道哪个有效哪个无效。

正确做法：先统计哪类问题最多，只改那一类，测试验证后再改下一类。

**原则 2：改 Prompt 要加不要删**

每次调优时，在原有 Prompt 基础上追加指令，而不是重写。这样能保留已经调好的部分。

**原则 3：记录每次修改**

每次修改 Prompt 时，在文件头部记录：
```
# 调优日志
## v2 — 2026-04-18
- 修改：强化追问策略（A类问题）
- 测试：Q1-Q4 重新测试，Q2/Q3 改善，Q1/Q4 需要继续优化
```

### 3.3 什么时候该停止调优

调优不是无限的。达到以下标准就可以进入下一阶段：

- 20 题中 ✅通过 ≥ 14 题（70%）
- ❌不通过 ≤ 2 题（10%）
- 没有编造数据的问题（C类 = 0）

## 五、常见调优案例

### 案例 1：Agent 不追问，直接给泛泛的建议

**诊断**：A 类问题
**修改**：在 Prompt 的追问策略部分加一句：
```
重要：如果用户没有告诉你省份、分数、选科中的任意一项，
你必须在回答末尾追问缺失的信息。宁可少给建议，也不要在信息不全时给具体推荐。
```

### 案例 2：Agent 编造了一个不存在的分数线

**诊断**：C 类问题
**修改**：加一条绝对规则：
```
绝对禁止：不要编造任何录取分数线。
如果你不确定某个分数是否准确，就说"这个数据我不确定，建议去官网核实"。
宁可说不知道，也不要给一个可能错误的数字。
```

### 案例 3：回答太长，信息密度低

**诊断**：E 类问题
**修改**：在回答规范中加：
```
回答结构模板：
1. 第一句话直接给结论（"你这个分数，我建议报XXX"）
2. 2-3个要点支撑（每个要点1-2句话）
3. 一个追问收尾

不要写背景介绍、不要写"让我来帮你分析"、不要写总结段落。
```

### 案例 4：Agent 知道数据但没引用

**诊断**：F 类问题
**排查**：
1. 先看 Dify 日志 → 知识检索节点有没有返回结果
2. 如果返回了但 LLM 没引用 → Prompt 中加：
   ```
   如果参考资料中包含与用户问题相关的分数线数据，你必须引用：
   "根据数据，XXX大学2024年在河北物理类最低录取分数是XXX分"
   ```
3. 如果检索结果为空 → 调整 Top K 或 Score 阈值

## 六、进阶：A/B 测试

当你不确定两种 Prompt 写法哪个更好时：

1. 准备 5 道关键测试题
2. 用 Prompt A 跑一遍，记录回答
3. 改成 Prompt B，跑同样的 5 道题
4. 对比两次回答，选更好的版本

这在调优中后期特别有用——微调措辞时，A/B 测试能避免"改了反而变差"。
