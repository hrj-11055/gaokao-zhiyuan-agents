# P0 用户价值上线方案

更新日期：2026-06-02

## 目标

上线前只回答一个问题：用户付费 19.9 元后，能不能稳定拿到他认为值这个价格的结果。

这个结果不是“支付成功”，而是：

- 一份能打开的完整志愿参考报告。
- 对学校和专业的明确判断。
- 对冲稳保、专业适配、城市/预算等风险的提醒。
- 用户和家长看完后知道下一步该查什么、问什么、避开什么。
- 发生支付或生成异常时，能找到客服并得到补开、补发或解释。

## 解决方案

### 1. 把付费前置条件说清楚

首页和报告页统一成四步：

1. 填写基础资料：省份、科类、分数决定推荐边界。
2. 完成 1 轮 AI 咨询：补充城市、专业、预算和家庭约束。
3. 完成两项测评：性格类型定位 + 霍兰德职业兴趣，补充分数之外的专业适配依据。
4. 解锁并生成完整报告：输出判断、风险提醒和下一步行动。

任何一步没完成，下一步都要告诉用户差什么，以及点哪里继续。

### 2. 把 19.9 元权益具体化

所有入口统一表达为：

- 完整志愿报告：学校/专业判断、风险提醒、行动建议。
- 院校/专业深度阅读：在线阅读不限次数。
- PDF 下载额度：深度报告 PDF 下载额度以会员状态页显示为准。
- 客服兜底：支付成功未解锁、报告生成失败、PDF 下载异常可添加客服微信 `HRJ-11055`。

避免只写“VIP”。可以保留“VIP”作为状态名，但必须跟着具体权益。

### 3. 把邀请 5 人规则具体化

有效邀请必须同时满足：

- 被邀请人是新用户。
- 通过邀请人的分享路径进入。
- 被邀请人完成基础资料：省份、科类、分数。

不满足这些条件，不计入有效邀请。页面要显示当前进度，例如 `2/5`。

### 4. 把信任闭环前置

用户在高考志愿场景里最怕“乱推荐”和“付了钱没人管”。上线前必须展示并验收：

- 报告生成时间。
- 结果仅供参考，最终以省教育考试院和高校官方信息为准。
- 隐私保护入口可访问。
- 客服微信和用户 ID 能被找到。
- 异常处理口径一致。

### 第 3 步：邀请链路验收

- [x] 邀请页或会员卡显示当前有效邀请进度。Codex 自动验收：首页、报告页、我的页均展示有效邀请进度。
- [x] 页面说明“新用户 + 完成基础资料”才算有效邀请。Codex 自动验收：首页、报告页、我的页和客服文档均有规则说明。
- [ ] 被邀请新用户完成省份、科类、分数后，邀请人进度增加。
- [ ] 满 5 个有效邀请后，邀请人会员状态变为 `active/invite`。
- [ ] 已注册用户、自己邀请自己、未完成资料都不计数。

### 第 4 步：报告质量验收

每份报告必须包含：

- [ ] 基础画像：省份、科类、分数等输入被正确使用。
- [ ] 学校/专业判断：不是只给泛泛建议。
- [ ] 风险提醒：至少包含录取风险、专业适配风险或费用/地域风险之一。
- [ ] 下一步行动：告诉用户该查招生计划、分数线、专业限制或联系学校确认什么。
- [ ] 官方核对提示：明确最终以省教育考试院和高校官方信息为准。

### 第 5 步：客服兜底验收

- [x] 我的页能看到客服微信。Codex 自动验收：`profile.vue` 展示客服微信和二维码入口。
- [x] 支付失败、支付确认中、报告失败时能看到客服处理方式。Codex 自动验收：报告页和我的页异常弹窗均包含客服路径。
- [x] 客服能按用户 ID、支付截图、问题时间定位问题。Codex 自动验收：客服文档通用取证清单已覆盖。
- [x] 支付成功未解锁有补开口径。Codex 自动验收：客服文档已有支付成功未解锁 SOP。
- [x] 重复扣款有退款或补偿口径。Codex 自动验收：客服文档已有重复扣款和退款异常 SOP。
- [x] 邀请不计数有规则解释口径。Codex 自动验收：客服文档新增邀请人数没有增加 SOP。
