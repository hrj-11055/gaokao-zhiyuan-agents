# 高考志愿填报项目：从 0 到 1 构建方法论

本文档总结了「峰哥咨询参考」高考志愿填报项目在开发、商业化、运营及工程实践等方面的核心方法论。这不仅仅是针对该项目的业务总结，更是为了沉淀一套可复用的「独立产品构建闭环经验」，确保未来在做其他项目时能少走弯路。

## 1. 核心底座：数据获取的决定性作用
在高考志愿填报这种信息高度不对称的领域，**数据获取能力就是核心壁垒和产品基础**。
- **数据是 AI 的灵魂**：大语言模型（如 DeepSeek/Gemini）的底层能力是推理，但如果没有准确的分数线、权威的专业目录、详细的院校背景数据（如 Citadel 计划所需的 360 度数据），AI 产生的只是好听的废话甚至幻觉。
- **实施路径**：
  - 构建健壮的数据清洗与抓取脚本（例如 `data/crawl_scores_v5.py`）。
  - 将非结构化数据提炼为 AI 易于理解的知识库格式（Markdown/JSON），并构建自动化的知识注入流（如 `data/upload_to_dify.py`）。
  - 在这个赛道，**持续且高质量的数据更新**，比单纯微调 Prompt 更能直接提升用户感知的准确度。

## 2. 竞品策略：借鉴 Top1 与差异化打击
- **如何「抄」 Top1**：不要闭门造车。直接深入研究市面上最头部的产品（如夸克高考、掌上高考等），拆解它们的核心架构。把验证过的、用户习以为常的功能（基础的分数查询、位次推荐算法、核心表单结构）快速复刻过来，作为我们的基建，降低用户的教育成本。
- **如何打差异化**：巨头都在做「浅层的、海量的数据检索」，我们就做「极度深度的、定制化的研究」。
  - 避开硬碰硬的大众化推荐，转而聚焦**深度洞察**：引入 AI 智能体对话（Dify）、七大模块的「专业深度研究报告」、院校 360 度剖析以及「家庭战略会议」沟通指南。
  - 用极具深度的 PDF 报告和类似「峰哥」的拟人化专业咨询，对传统的「冷冰冰数据表格工具」形成降维打击。

## 3. 产品节奏：MVP、"先做个垃圾" 与经验闭环
- **"先做一个垃圾出来，然后慢慢改"**：这并不是鼓励粗制滥造，而是为了**克制完美主义**，强行推进执行力。核心目标是第一时间跑通**端到端**的全流程（从用户前端表单 -> 触发网关 -> 代理服务流式 SSE -> Dify/模型 -> 渲染报告）。
- **认知的升维与闭环**：
  - 必须要清醒地认识到：**慢慢改一个"垃圾"，并不一定能让用户觉得值得购买**。用户为价值买单，而不是为你的努力买单。
  - 这种策略的真正意义在于**跑通全链路的体感**。通过这个过程，你亲自踩过了支付接入的坑、高并发限流的坑、服务器本地调试与线上部署的坑。
  - 把这些从零到一的经验沉淀下来形成完整的**闭环**。当你在探索中找到了正确的商业道路，下一次再起盘新项目时，你将拥有上帝视角，能避开 80% 的技术与决策弯路。

## 4. 增长与商业化：推广策略与裂变机制设计
再好的产品如果没有分发渠道，也会死在自己的服务器上。在产品功能开发的同时（甚至之前），就必须把**推广和裂变机制**设计在系统底层：
- **利益驱动的裂变网络**：比如系统内设计了 VIP 机制来解锁深度 PDF 报告下载。用户可以选择直接付费（如 19.9 元买断），也可以通过**邀请 5 名新用户有效注册**来免费解锁。
- **高价值诱饵的设计**：将「大学/专业深度在线 HTML 阅读」作为免费体验项（提供信任感和试用价值），而将易于保存、打印、高浓度的「最终决策 PDF 报告」作为钩子，促使家长为了获取报告而分享到朋友圈或班级群。
- **匹配用户心理**：结合微信小程序的社交生态，利用高三家长群体高度焦虑、极度渴望信息确认的心理特征，设计一键生成的分享海报和卡片。

## 5. 工程与研发实践：版本管理、同步与 AI 协作工具
随着项目迭代，规范的工程化管理是保证快速开发且"不翻车"的关键：
- **环境隔离与代码同步**：
  - 明确分离职责：159 服务器负责 AI 编排（Dify）与数据库核心，47 服务器负责业务网关与代理。
  - 坚持良好的同步习惯。本地开发小程序必须使用 `npm run dev:mp-weixin` 保证热更新体验，确认无误后才执行 build，最后再推向远端服务器或微信审核。
- **Git 规范与自动化 (Hooks)**：
  - 建立严格的 Git 规范（如使用 Conventional Commits 标准：`feat:`, `fix:`, `docs:` 等），保证每次提交可追溯。
  - 引入 Git Hooks（例如 `husky` 配合 `lint-staged`），在代码提交前强制执行格式化（Prettier）和语法检查（ESLint），保持代码库的绝对整洁。
- **全面拥抱 AI 提效 (Codex/Gemini 工具)**：
  - **AI 结对编程**：让 AI 帮你处理脏活累活（复杂的正则匹配、大量的样板代码生成、单元测试覆盖）。
  - **文档驱动 AI**：维护详尽的 `docs/` 和 `AGENT.md` / `GEMINI.md`。当项目拥有清晰的上下文背景时，AI 开发助手才能真正理解项目架构，从而精准地提供架构建议、完成本地代码到服务器部署脚本的编写。

## 6. 合规与基础设施：备案、支付与踩坑经验
在独立开发中，最让人劝退的往往不是代码逻辑，而是各种繁琐的资质合规与基础设施配置。这些是纯正的「踩坑经验」，只有亲历过才知道其中的细节：
- **服务器资源采购与配置**：需要购买哪些服务器？例如我们区分了 159 服务器（运行 Dify 和数据库，对算力和内存要求高）与 47 服务器（运行 Node 代理，处理网关请求）。如何配置域名解析、SSL 证书等。
- **网站与服务器备案**：需要进行 ICP 域名备案、公安联网备案，稍有不慎就会被驳回。了解这些周期，能帮助你在开发早期就并行推进合规流程，避免“代码写完了却无法上线”的窘境。
- **小程序多重审核与备案**：微信小程序的合规极度严格，且**不是一次备案完就完事了**。除了初始信息备案，如果涉及到支付、UGC（用户生成内容）或教育咨询类目，还需要多次类目审核和相关资质补充。
- **微信支付接入**：微信商户号的申请、公钥私钥的配置、支付回调接口的安全校验。这些环节极其繁琐容易报错，亲手跑通后，这就成了你独立变现的基础护城河。

## 7. 全生命周期管理：从 0 到 1 独立开发实战
这个项目并非凭空臆想，而是严格遵循了标准的产品全生命周期管理方法论，是一场真正的「全栈单兵作战」实盘演练：
- **市场与竞品分析**：研究高考志愿填报焦虑情绪背后的痛点，拆解头部竞品的优劣势。
- **Idea 与产品设计**：确定了“深度的定制化研究”作为破局点，将线下的咨询流程产品化。
- **UI/UX 交互设计**：考虑到家长群体的使用习惯，界面设计追求克制与直观，结合小程序的原生体感。
- **全栈工程构建**：从 Python 数据抓取，到 Dify 工作流编排，再到 Node.js 后端代理与 Vue 前端界面，一个人拉通了前中后台系统。
- **功能迭代与优化**：不断从 MVP 中吸收反馈，优化架构、提升并发性能、改善流式输出体验。
- **测试与品控**：通过 Python 脚本（如 `check_reports.py`）实现批量质量校验，确保最终生成的报告不翻车。
- **推广与营销（规划中）**：在系统底层设计好 VIP 裂变和海报分享机制后，为后续的市场推广打好地基。
