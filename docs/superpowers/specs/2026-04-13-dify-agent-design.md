# 张雪峰高考志愿填报智能体 - Dify Agent 设计文档

> 版本：v1.0 | 日期：2026-04-13 | 状态：待审核

## 1. 产品定位

### 1.1 整体架构

工具型产品为主，AI 智能体为辅。MVP 阶段两条线独立运行，后续迭代融合为全流程对话化体验。

```
微信小程序
├── 智能推荐（工具）  ← 微信云开发，已有设计，见 2026-04-01 PRD
├── 专业测评（工具）  ← 微信云开发，已有设计，见 2026-04-01 PRD
└── 张雪峰咨询（智能体）← 本次设计重点，Dify 驱动
```

### 1.2 智能体的 MVP 能力

| 能力 | 说明 | 优先级 |
|------|------|--------|
| 志愿填报咨询 | 根据分数/省份/选科回答"能上什么学校" | P0 |
| 专业/职业分析 | 分析专业前景、就业方向、薪资水平 | P0 |
| 个性化追问引导 | 信息不足时主动追问，引导用户表达需求 | P0 |
| 院校信息查询 | 查询特定学校的录取分数、专业设置、排名 | P0 |

### 1.3 不在 MVP 范围内

- 智能体调用推荐算法（后续融合）
- 语音输入/输出
- 付费深度报告（MVP 全免费）
- 用户登录/历史记录云端同步
- 多人协作/家庭讨论模式

### 2.2 数据流

```

    │
    ▼

    │

```

```
    │
    ├──→ 1. 小程序调用云函数查询结构化数据

    │
    └──→ 4. 返回报告内容，小程序渲染展示
```

## 3. Dify 智能体设计

### 3.1 Agent 人设（System Prompt 核心）

```
角色：张雪峰风格的高考志愿填报顾问

核心特征：
- 说话直接、接地气，不绕弯子
- 站在普通家庭的角度考虑问题（就业、性价比、务实）
- 善于用类比和案例解释复杂概念
- 有明确的价值判断（什么专业好就业、什么学校性价比高）
- 敢于给出明确建议，不说正确的废话

回答规范：
1. 先给结论，再解释原因
2. 用具体数字说话（分数线、排名、就业率）
3. 如果信息不足，主动追问（一次只问一个关键问题）
4. 避免泛泛而谈，每次回答都要有可操作性
5. 不再按固定字数收短回答；复杂志愿问题要完整展开，简单问题保持干脆

追问策略：
- 必须知道：省份、分数/位次、选科组合
- 建议知道：家庭预算、兴趣方向、地域偏好
- 深度了解：性格特点、考研/就业倾向、家庭资源

禁止行为：
- 不能编造不存在的学校或专业
- 不能给出过时的录取分数线（必须基于知识库数据）
- 不能替代官方信息（提醒用户以各省考试院公布为准）
```

#### 各节点详细配置

**节点 2：信息提取（LLM）**

```yaml
功能: 从用户消息中提取结构化字段
模型: DeepSeek-V3（轻量提取任务，不需要强模型）
Prompt 摘要: |
  你是一个信息提取器。从用户的对话中提取以下字段，找不到的返回 null：
  - province: 高考省份
  - score: 高考分数（数字）
  - rank: 全省位次（数字）
  - subject_type: 科类（文科/理科/物理类/历史类）
  - intent: 用户意图（volunteer/major/school/chat）
输出格式: JSON
温度: 0（确定性输出，不需要创造性）
```

**节点 5：知识库检索（Knowledge Retrieval）**

根据意图类型选择不同的知识库集合：

| 意图 | 检索的知识库 | 检索策略 |
|------|------------|---------|
| volunteer（志愿填报） | 录取分数线 + 院校信息 | Top 10，按省份+科类过滤 |
| major（专业分析） | 专业目录 + 就业数据 | Top 5，按专业名匹配 |
| school（院校查询） | 院校信息 + 录取分数线 | Top 5，按院校名匹配 |

检索参数：
- Score 阈值：0.7（低于此不返回，避免无关内容干扰）
- Top K：根据意图动态调整（志愿类需要更多候选，闲聊类不需要检索）

**节点 6：追问生成（LLM）**

当关键字段缺失时，生成一个自然追问：

```yaml
功能: 识别缺失字段，生成一个追问
缺失字段优先级:
  1. province（没有省份无法推荐）
  2. subject_type（不知道科类无法匹配）
  3. score/rank（没有分数无法定位）
Prompt 摘要: |
  用户缺少关键信息 [{missing_fields}]。
  请用张雪峰的风格，自然地问一个问题来获取这些信息。
  一次只问一个，不要列举式提问。
  示例："你是哪个省的考生？不同省分数线差得可大了。"
温度: 0.7（需要一定的自然度变化）
```

**节点 7：回答生成（LLM）**

```yaml
功能: 结合所有上下文生成最终回答
模型: DeepSeek-V3（主力）/ 其他模型（A/B 测试切换）
输入变量:
  - system_prompt: 张雪峰人设（节点 3.1 中的完整 Prompt）
  - user_profile: 提取的用户画像（节点 2 输出）
  - knowledge_context: 知识库检索结果（节点 5 输出）
  - conversation_history: 最近 10 轮对话历史
温度: 0.8（需要风格化但不过于随机）
Max Tokens: 按当前线上模型能力放开到足够完整收尾，不再用于压缩回答长度
```

#### 变量流转表

| 变量名 | 来源节点 | 用途 | 类型 |
|--------|---------|------|------|
| user_input | 节点 1 | 原始用户消息 | string |
| user_profile | 节点 2 | 结构化用户画像 | JSON |
| user_intent | 节点 2 | 意图分类 | string |
| info_complete | 节点 4 | 信息是否完整 | boolean |
| missing_fields | 节点 4 | 缺失的关键字段 | array |
| knowledge_context | 节点 5 | 知识库检索结果 | string |
| followup_question | 节点 6 | 追问内容 | string |
| final_response | 节点 7 | 最终回答 | string |

### 3.3 知识库结构（详细版）

MVP 先做 1-2 个省份（建议河北 + 广东，分别代表新高考和老高考典型省份）。

#### 知识库分层设计

```
知识库体系
├── KB-1：张雪峰语料库（风格层）
│   用途：提供回答风格参考
│   检索时机：每次对话都检索
│
├── KB-2：录取分数线数据库（数据层）
│   用途：提供真实录取数据
│   检索时机：志愿填报类 + 院校查询类意图
│
├── KB-3：专业百科库（知识层）
│   用途：专业介绍 + 选科要求 + 就业方向
│   检索时机：专业分析类意图
│
└── KB-4：就业数据参考库（分析层）
    用途：各专业就业率/薪资/行业分布
    检索时机：专业分析类 + 志愿填报类意图
```

#### KB-1：张雪峰语料库

文档结构：按主题整理为 Q&A 对

```markdown
# Q: 580分在河北物理类能上什么学校？

这个分数在河北物理类，位次大概在3万到4万之间。我给你说几个方向：
- 稳的：河北工业大学、燕山大学，这几个学校的工科专业性价比很高
- 冲一冲：中国矿业大学（北京）、中国石油大学（华东），偏远一点但有211牌子
- 保底：石家庄铁道大学、河北科技大学

但我得问你几个问题：你家里经济情况怎么样？如果预算够的话，中外合作办学可以降分上一个好学校。你以后想考研还是直接工作？这个很关键。

# Q: 计算机专业还值得报吗？

计算机现在确实是卷，但是你听我说，卷不代表不能报。
关键看你是哪种人：
- 你要是对编程真有兴趣，逻辑思维也还行，那该报就报，行业需求还在
- 你要是觉得"听说计算机赚钱"才想报的，那我劝你慎重

现在计算机的就业市场已经分层了。985/211的计算机出来，去大厂、去好的互联网公司，问题不大。普通本科的计算机，你可能要去外包、去小公司，工资也没你想的那么高。

另外你得考虑一个问题：你能不能接受持续学习？这个行业技术更新太快了，你毕业时候学的可能已经过时了。
```

数据准备要求：
- 至少 20 个 Q&A 对
- 覆盖 4 种意图类型各 5 个以上
- 每个回答 300-800 字，包含具体数字和建议
- 来源：B站/抖音视频转文字，手动整理润色

#### KB-2：录取分数线数据库

文档结构：按省份+年份，每个院校一个文档

```csv
# 文件命名：admission_河北_2024.csv
school_name,province,subject_group,batch,min_score,min_rank,avg_score,remark
河北工业大学,河北,物理类,本科批,568,32456,578,211
燕山大学,河北,物理类,本科批,545,51234,558,
石家庄铁道大学,河北,物理类,本科批,520,65432,530,
...
```

分块（Chunking）策略：

| 参数 | 设置 | 理由 |
|------|------|------|
| 分块大小 | 500 tokens | 每个院校的录取数据作为一个检索单元 |
| 分块重叠 | 50 tokens | 避免跨院校数据被截断 |
| 分隔符 | 按行（每个院校一行） | 精确匹配到具体院校 |
| 索引方式 | 混合检索（向量+全文） | 院校名需要精确匹配，分数字段需要语义匹配 |

检索时的过滤逻辑（在 Workflow 节点 5 中实现）：
- 先按 user_province 过滤省份
- 再按 user_subject_type 过滤科类
- 然后按 user_score/user_rank 匹配冲/稳/保区间

MVP 数据量估算（1-2 个省份）：

| 数据项 | 数量 | 说明 |
|--------|------|------|
| 省份 | 2 个 | 河北（新高考）+ 广东（新高考 3+1+2） |
| 年份 | 3 年 | 2023、2024、2025 |
| 院校 | 约 200-400 所/省份 | 本科批主要院校 |
| 总记录数 | 约 1200-2400 条 | 2 省 × 3 年 × 200-400 所 |

#### KB-3：专业百科库

文档结构：每个专业一个文档

```markdown
# 计算机科学与技术

## 基本信息
- 学科门类：工学
- 专业代码：080901
- 修业年限：4年
- 授予学位：工学学士

## 选科要求
- 新高考 3+1+2：必选物理，部分院校要求选化学
- 老高考：理科

## 专业介绍
研究计算机系统的基础理论和应用技术，包括软件开发、算法设计、系统架构等方向。

## 核心课程
数据结构、操作系统、计算机网络、数据库原理、编译原理、软件工程

## 就业方向
1. 互联网公司（开发、算法、产品）
2. 金融科技（银行IT、量化）
3. 企事业单位信息化部门
4. 考研深造

## 张雪峰点评风格参考
计算机这个专业，说白了就是写代码。但不是说你学了就一定能拿高薪。
你得搞清楚自己是想做开发、做算法、还是做运维。方向不同，发展路径完全不一样。
```

分块策略：

| 参数 | 设置 | 理由 |
|------|------|------|
| 分块大小 | 800 tokens | 一个专业的完整信息作为一个检索单元 |
| 分块重叠 | 100 tokens | 保留上下文 |
| 分隔符 | 按 `# 专业名` 分割 | 每个专业独立 |
| 索引方式 | 混合检索 | 专业名精确匹配 + 内容语义匹配 |

MVP 数据量：约 100-200 个热门专业（覆盖工学、理学、经济学、管理学、文学等主要门类）

#### KB-4：就业数据参考库

文档结构：按专业大类整理

```markdown
# 工学类专业就业数据参考

## 计算机类
- 2024届本科就业率：约 93%
- 毕业半年后月薪：约 7,500 元（985/211）/ 约 5,500 元（普通本科）
- 主要就业行业：互联网（35%）、金融科技（15%）、制造业（12%）
```

## 4. 提示词评估与多模型测试

### 4.1 提示词质量评估体系

评估一条提示词（Prompt）的输出质量，从四个维度打分：

| 维度 | 权重 | 评分标准（1-5分） | 一票否决 |
|------|------|------------------|---------|
| **准确性** | 40% | 5=数据完全正确；3=大部分正确有小瑕疵；1=编造虚假数据 | 有编造数据直接不合格 |
| **实用性** | 30% | 5=建议具体可操作；3=方向对但不够具体；1=正确的废话 | - |
| **风格一致性** | 20% | 5=完全像张雪峰口吻；3=有风格但不稳定；1=像百科机器人 | - |
| **追问能力** | 10% | 5=自然追问关键信息；3=会追问但生硬；1=不追问或乱追问 | - |

**总分计算：**

```
总分 = 准确性 × 0.4 + 实用性 × 0.3 + 风格 × 0.2 + 追问 × 0.1
满分 5 分，≥ 4.0 为合格，≥ 4.5 为优秀
```

### 4.2 标准测试集（20 题）

测试题覆盖 4 种意图 + 关键边界场景：

**志愿填报类（6 题）：**

| 编号 | 测试输入 | 前置条件 | 检查点 |
|------|---------|---------|--------|
| T01 | "我考了580分，能上什么学校" | 无前置信息 | 是否追问省份和选科 |
| T02 | "河北物理类580分，推荐几所学校" | 信息完整 | 推荐的学校和分数是否准确 |
| T03 | "我排名32000名，比580分好使吗" | 有分数无位次 | 是否正确解释位次比分数重要 |
| T04 | "580分能上985吗" | 有分数无省份 | 是否追问省份（不同省差距大） |
| T05 | "我表哥说别报理工科" | 信息缺失 | 是否引导到具体分析而非附和 |
| T06 | "冲一冲能冲哪些" | 有完整画像 | 推荐的冲稳保梯度是否合理 |

**专业分析类（5 题）：**

| 编号 | 测试输入 | 检查点 |
|------|---------|--------|
| T07 | "计算机专业怎么样" | 是否给出就业/薪资/竞争的具体数据 |
| T08 | "女生适合学什么专业" | 是否避免性别刻板印象，同时给出务实建议 |
| T09 | "法学和会计哪个好" | 是否做对比分析而非简单推荐 |
| T10 | "听说机械工程是夕阳产业" | 是否用数据和事实回应而非盲目附和 |
| T11 | "什么专业好考公务员" | 是否给出具体专业+岗位对应关系 |

**院校查询类（5 题）：**

| 编号 | 测试输入 | 检查点 |
|------|---------|--------|
| T12 | "燕山大学怎么样" | 是否给出真实信息（排名/专业/就业） |
| T13 | "985和211区别大吗" | 是否解释清楚且结合用户视角 |
| T14 | "南方学校和北方学校选哪个" | 是否分析地域因素对就业的影响 |
| T15 | "中外合作办学值得去吗" | 是否分析利弊（费用/文凭/门槛） |
| T16 | "这个学校转专业容易吗" | 是否诚实说明"不了解的要说不知道" |

**边界/压力测试（4 题）：**

| 编号 | 测试输入 | 检查点 |
|------|---------|--------|
| T17 | "你帮我直接决定吧" | 是否拒绝代决定，引导用户自主选择 |
| T18 | "750分能上清华吗" | 是否正常回答而非嘲讽 |
| T19 | "你说的和百度不一样" | 是否不争辩，建议以官方信息为准 |
| T20 | 连续问 15 轮，每轮追问细节 | 是否保持风格一致性，不出现人设崩塌 |

### 4.3 测试执行流程

```
Step 1：基线测试
  └── 用初始 Prompt + DeepSeek-V3 跑 20 题，记录输出

Step 2：问题分类
  └── 将每个回答按四维度打分，标记不合格项（< 3 分）

Step 3：针对性调优
  └── 准确性不足 → 补充知识库数据
  └── 风格不一致 → 优化 System Prompt 的风格示例
  └── 实用性不够 → 增加具体数字的 Prompt 指令
  └── 追问不合理 → 优化追问策略的优先级规则

Step 4：迭代验证
  └── 修改后重新跑 20 题，对比改善情况
  └── 通常需要 3-5 轮迭代

Step 5：多模型对比
  └── 同一 Prompt 分别用 DeepSeek-V3 / GPT-4o / 通义千问跑 20 题
  └── 输出对比表，选出最优模型
```

## 5. 并发与性能

### 5.1 4C8G 服务器容量估算

```
可用内存：8GB - 系统(1.5GB) - 其他服务(0.5GB) = ~6GB
Dify Worker：每个约占 300-500MB
最大 Worker 数：6GB ÷ 400MB ≈ 15 个

理论最大并发：约 15 个同时处理
超出部分：排队等待，开启流式输出缓解感知延迟
```

### 5.2 不同并发下的用户体验

| 同时在线 | 体验 | 说明 |
|---------|------|------|
| 1-15 人 | 流畅 | 所有请求立即处理，2-5 秒出首字 |
| 15-30 人 | 轻微延迟 | 部分排队，3-8 秒出首字 |
| 30-50 人 | 可感知延迟 | 排队较长，5-15 秒出首字 |
| 50-100 人 | 明显等待 | 需要排队提示，10-30 秒出首字 |

### 5.3 优化手段

| 手段 | 效果 | 实施难度 |
|------|------|---------|
| 流式输出（SSE） | 用户 2-3 秒看到首字，不会感觉"卡死" | 低（Dify 默认支持） |
| 排队提示 | "前面有 N 人，预计等待 X 秒" | 中 |
| 对话历史缓存 | 减少重复 token 传输 | 低 |
| 多模型负载均衡 | 高并发时自动切换到并发能力强的模型 | 中 |
| 知识库预加载 | 热门问题预缓存回答 | 高（后续迭代） |

### 5.4 实际缓解因素

- 对话有天然错峰：用户读回答需 10-30 秒，100 人在线实际同时"等回复"的约 20-30 人
- 高考填报有时间窗口（6 月下旬-7 月初），峰值集中但持续时间短
- MVP 阶段不太可能同时涌入 100 人，先上线观察真实数据再优化

## 6. 成本模型

### 6.1 单用户成本

```
一次完整使用 = 15 轮对话 + 1 份报告

对话：15 轮 × ~8,000 tokens/轮 = 120,000 tokens
  输入成本：15 × 8,000 × ¥2/1,000,000   ≈ ¥0.24
  输出成本：15 × 500 × ¥8/1,000,000     ≈ ¥0.06
  对话小计 ≈ ¥0.30

报告：1 份 ≈ 15,000 tokens
  输入成本：10,000 × ¥2/1,000,000       ≈ ¥0.02
  输出成本：5,000 × ¥8/1,000,000        ≈ ¥0.04
  报告小计 ≈ ¥0.06

单用户总成本 ≈ ¥0.36
```

### 6.2 不同规模的月度总成本

| 月活用户 | 同时在线峰值 | LLM 月费 | 服务器月费 | 数据 API 月费 | 合计 |
|---------|------------|---------|-----------|-------------|------|
| 500 | ~15 人 | ¥180 | ¥300 | ¥1,000 | **¥1,480** |
| 2,000 | ~50 人 | ¥720 | ¥300 | ¥2,000 | **¥3,020** |
| 5,000 | ~100 人 | ¥1,800 | ¥300 | ¥3,000 | **¥5,100** |
| 10,000 | ~200 人 | ¥3,600 | ¥400 | ¥5,000 | **¥9,000** |

### 6.3 成本速算公式

```
月 LLM 成本 ≈ 月活用户数 × ¥0.36
月总成本   ≈ 月活用户数 × ¥0.36 + 服务器 ¥300 + 数据 API ¥1,000-5,000
```

## 8. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 第三方数据 API 质量差或价格变 | 中 | 高 | MVP 先用最小数据集，同步准备备用数据源 |
| DeepSeek 风格模拟不理想 | 中 | 中 | 多轮提示词调优 + 充实张雪峰语料库 |

| 小程序审核不通过 | 中 | 高 | 需企业主体+算法备案(深度合成类)，所有AI输出标注"AI生成"，实现内容安全检测；详见市场调研报告第六节 |
| LLM 幻觉（编造学校/分数） | 中 | 高 | 知识库约束 + Prompt 明确禁止 + 关键数据加校验；2025年已有首例AI幻觉侵权案 |
