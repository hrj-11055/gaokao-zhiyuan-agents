# 大学评估报告数据清洗与重构设计说明 (Design Spec)

## 1. 目标
提升《大学深度研究报告》的阅读体验。具体目标为：
1. **剥离 JSON 数据**：将报告末尾用于系统解析的结构化数据（模块九）物理隔离，独立保存。
2. **清洗标记词汇**：在保留原文本语义的前提下，移除报告正文中影响阅读体验的临时标记词（如“待核实”、“未检索到数据”等）。
3. **安全第一**：在修改任何文件前，建立完整的物理备份。

## 2. 处理范围
- **初始范围**：仅针对 `data/大学评估报告/` 目录下的 `.md` 文件。
- **后续扩展**：大学报告处理验证无误后，再复用脚本处理 `data/专业评估报告/` 目录。

## 3. 架构与流程设计

### 3.1 阶段一：备份与物理剥离 (Rule-based)
1. **备份机制**：
   - 脚本启动时，创建一个时间戳目录 `data/report-cleaning-backups/univ-reports-[TIMESTAMP]/`。
   - 将目标目录下所有的 `.md` 文件拷贝至备份目录。
2. **JSON 剥离逻辑**：
   - 目标目录：创建 `data/大学评估报告_json/`。
   - 正则匹配：匹配标记 `## 模块九：结构化数据导出 (JSON)`（或类似的模式）及其之后的所有内容。
   - 提取内容中包裹在 ```json ... ``` 块内的数据。
   - 将提取的 JSON 数据存入 `data/大学评估报告_json/{文件名}.json`。
   - 从原 Markdown 字符串中截断/删除这部分内容。

### 3.2 阶段二：智能语义清洗 (LLM-based)
1. **清洗对象**：
   - 经过阶段一剥离了末尾 JSON 后的纯净 Markdown 文本。
2. **清洗工具**：
   - 使用 **Gemini 2.5 Flash** 模型 (`gemini-2.5-flash`)。
3. **清洗逻辑与 Prompt 设计**：
   - **输入**：包含脏标记的 Markdown 文本段落。
   - **指令（Prompt）**：
     “你是一个专业的文字编辑。请帮我清洗以下 Markdown 报告中的临时标记。
     1. 删除所有类似 `[待核实]`, `[未检索到]`, `未确定`, `[部分待核实]` 等表示数据不确定的标签词汇。
     2. 如果删除标记导致句子不通顺（例如表格中的某项仅剩一个单独的括号，或“来源：”后无内容），请做语义顺滑处理（如改为“暂无数据”或直接删除该行废话）。
     3. 绝对不能修改原文的其他实质性内容、数据和 Markdown 格式结构。
     4. 如果原文包含 ‘8.2 未检索到数据清单’ 这种整块都是无用信息的章节，请直接将该小节及内容整体删除。”
   - **输出**：清洗后的纯净 Markdown 文本。
4. **回写原文件**：将大模型返回的文本覆盖写入原 `.md` 文件中。

## 4. 测试与验证策略
1. **冒烟测试 (Smoke Test)**：
   - 选取 1-2 份典型的报告（如 `三峡大学.md`）作为样本进行测试。
   - 检查 JSON 文件是否成功分离且格式合法。
   - 人工校验 Markdown 清洗结果是否符合预期。
2. **全量执行**：
   - 测试通过后，执行批量处理脚本，提供进度条和重试机制（针对 API 调用超时）。

## 5. 后续步骤
完成大学评估报告处理后，复审本说明，并启动针对 `专业评估报告` 的清洗流程。
