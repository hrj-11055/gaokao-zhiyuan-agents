## 1. 产品概述

### 1.1 产品背景

2025 年高考报名人数 **1,335 万**，志愿填报付费市场规模 **10.9 亿元**（艾媒咨询）。88.1% 的高考生愿意付费获取志愿填报服务，但市场存在严重的信息不对称和服务分层：

- **大厂免费工具**（夸克/百度/腾讯）：数据齐全但推荐中立、模板化，缺乏个性化深度
- **人工咨询**（张雪峰/峰学蔚来 12,999-18,999 元）：有态度、有深度，但价格昂贵且名额稀缺
- **市场空白**：缺少"有态度的 AI + 低价普惠"的中间档产品

同时，2025 年新京报实测 10 款 AI 志愿产品发现，头部大厂产品普遍存在位次定位失误、选科限制忽视、推荐已撤销专业等严重问题，用户对"靠谱的 AI 志愿工具"有强烈需求。

### 1.2 产品定位

**一句话定位**：张雪峰风格的 AI 志愿填报助手 — 工具查数据，智能体给建议。

**定位公式**：

```
大厂产品 = 数据工具（冷冰冰、中立、标准化）
张雪峰本人 = 万元咨询（有态度、深度、但贵且稀缺）
我们 = 张雪峰风格的 AI（有态度 + 深度追问 + 低价普惠）
```

### 1.3 产品形态

微信小程序，包含三大功能模块：

```
高考志愿填报助手（微信小程序）
├── 智能推荐（工具）  ← 微信云开发
├── 专业测评（工具）  ← 微信云开发
└── 张雪峰咨询（AI 智能体）← Dify 驱动
```

### 1.4 产品目标

| 目标 | 衡量指标 | MVP 目标值 |
|------|---------|-----------|
| 降低信息门槛 | 推荐结果加载时间 | < 3 秒 |
| 提供有态度的建议 | 对话完成率（15 轮） | > 60% |
| 数据可靠性 | 幻觉率（编造数据） | < 5% |
| 用户满意度 | "有用"评分 4 分以上占比 | > 70% |
| 商业验证 | 报告付费转化率 | > 10%（V1.2 上线后） |

## 2. 目标用户

### 2.1 用户画像

#### 用户 A：高考生

| 维度 | 描述 |
|------|------|
| 年龄 | 17-19 岁 |
| 场景 | 高考出分后需要快速了解能上什么学校、什么专业适合自己 |
| 信息渠道 | 抖音/B 站/小红书/知乎 |
| AI 接受度 | 高，愿意尝试 AI 工具 |
| 决策权 | 约 50%（另一半家长主导） |
| 付费能力 | 有限，可接受百元级消费 |
| 核心诉求 | "告诉我能上什么学校" + "什么专业适合我" |

#### 用户 B：家长

| 维度 | 描述 |
|------|------|
| 年龄 | 40-50 岁 |
| 场景 | 帮孩子选志愿，怕选错影响一生 |
| 信息渠道 | 微信/短视频/朋友推荐 |
| AI 接受度 | 中等，认为"AI 不够靠谱"，更信任有态度的专家 |
| 决策权 | 约 50%（另一半孩子自主） |
| 付费意愿 | 平均 3,000-5,000 元，部分可达万元 |
| 核心诉求 | "别选错" + "性价比高的学校" + "好就业的专业" |

### 2.2 用户痛点排序

| 排名 | 痛点 | 现有解决方案 | 未满足的原因 |
|------|------|------------|------------|
| 1 | AI 推荐结果不可靠/不一致 | 大厂免费工具 | 新京报实测：同一条件输入不同产品，9 所推荐院校仅 2 所重合 |
| 2 | 缺乏个性化深度建议 | 大厂 AI 志愿助手 | 回答中立模板化，不敢给明确建议 |
| 3 | 高价咨询不透明/买不起 | 张雪峰/峰学蔚来 | 12,999-18,999 元，预约排到 2026 年 |
| 4 | 选择焦虑（选项太多） | 各种工具 | 工具反而加剧了焦虑（30-112 个志愿选项） |
| 5 | 信息不对称 | 掌上高考/阳光志愿 | 数据有，但理解门槛高 |

## 4. 功能需求详细说明

### 4.1 首页

**功能描述**：展示三个功能入口，用户可快速进入任一模块。

**页面元素**：

| 元素 | 说明 | 交互 |
|------|------|------|
| 产品标题/Logo | "高考志愿填报助手" | - |
| 智能推荐入口 | 卡片式入口，图标+文字 | 点击跳转推荐输入页 |
| 专业测评入口 | 卡片式入口，图标+文字 | 点击跳转测评答题页 |
| 张雪峰咨询入口 | 卡片式入口，突出"AI"标签，头像图标 | 点击跳转对话页 |
| 免责声明 | "数据仅供参考，请以各省考试院公布为准" | 底部固定 |

**设计要求**：简洁清晰，三个入口一目了然，张雪峰咨询入口可适当突出（视觉引导用户发现差异化功能）。

### 4.2 智能推荐

#### 4.2.1 推荐输入页

**功能描述**：用户输入基本信息，系统基于录取数据进行推荐。

**输入字段**：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|---------|------|
| 高考省份 | 下拉选择 | 是 | 必选 | 31 个省份 |
| 高考分数 | 数字输入 | 是 | 0-750 整数 | 输入框带单位"分" |
| 全省位次 | 数字输入 | 否 | 正整数 | 提示"填写位次推荐更精准" |
| 科类 | 下拉选择 | 是 | 必选 | 根据省份自动适配：老高考→文/理，新高考→物理类/历史类 |

**交互说明**：
- 省份选择后，科类选项自动更新
- 点击"开始推荐"校验必填项，不通过则红框提示
- 推荐计算期间显示 loading 状态

#### 4.2.2 推荐结果页

**功能描述**：分三档展示推荐院校列表。

**页面结构**：

| 元素 | 说明 |
|------|------|
| 用户信息摘要 | 顶部显示"XX省 XX类 XXX分 / 位次XXXXX" |
| 三档 Tab | 冲 / 稳 / 保，默认显示"稳" |
| 院校卡片列表 | 按录取概率排序 |

**院校卡片信息**：

| 字段 | 说明 |
|------|------|
| 院校名称 | 如"河北工业大学" |
| 标签 | 985/211/双一流/普通 |
| 所在地 | "河北·天津" |
| 录取概率 | 百分比（如"78%"） |
| 近3年最低分 | "2024: 568 / 2023: 562 / 2022: 555" |
| 近3年最低位次 | "2024: 32456" |

**推荐算法规则**：

```
1. 优先使用位次排序（位次 > 分数）
2. 查询近3年同省份同学科组别的录取数据
3. 分档标准：
   - 冲：用户位次高于院校最低位次 10%-30%
   - 稳：用户位次在院校最低位次 ±10%
   - 保：用户位次低于院校最低位次 20% 以上
4. 新高考省份推荐精确到院校专业组级别
5. 每档至少推荐 5 所院校
```

#### 4.2.3 院校详情页

**功能描述**：展示单所院校的完整信息。

**页面结构**：

| 区域 | 内容 |
|------|------|
| 头部 | 院校名称 + 标签（985/211等）+ 所在地 |
| 基本信息卡 | 类型、简介、软科排名、校友会排名 |
| 历年分数线 | 表格：年份 / 最低分 / 最低位次 / 平均分 |
| 专业组列表 | 新高考：专业组名 + 选科要求 + 各组分数线 |
| 专业列表 | 老高考：专业名 + 各专业分数线 |

### 4.3 专业测评

#### 4.3.1 答题页

**功能描述**：通过 MBTI + Holland 两套测试，帮助考生了解性格类型和职业兴趣。

**测试内容**：

| 测试 | 题数 | 维度 | 输出 |
|------|------|------|------|
| MBTI 性格测试 | 约 20 题 | E/I, S/N, T/F, J/P | 4 字母类型（如 INTJ）+ 性格解读 |
| Holland 职业兴趣 | 约 20 题 | R/I/A/S/E/C | 前 3 个优势维度 + 推荐专业方向 |

**交互说明**：
- 进度条显示答题进度（如"3/20"）
- 每题 2 个选项，选择后自动进入下一题
- 支持本地缓存进度，退出后可继续
- 两套测试可分次完成

#### 4.3.2 测评结果页

**页面元素**：

| 元素 | 说明 |
|------|------|
| 性格类型 | 如"INTJ - 建筑师" |
| 维度分析 | 四个维度的倾向百分比可视化 |
| 推荐专业方向 | 3-5 个专业大类，每个附理由 |
| 操作按钮 | "查看匹配院校"→ 跳转智能推荐，优先展示相关专业 |

### 4.4 张雪峰咨询（AI 智能体）

#### 4.4.1 对话页

**功能描述**：用户以自然语言与 AI 智能体对话，获取张雪峰风格的志愿填报建议。

**页面结构**：

| 元素 | 说明 |
|------|------|
| 对话区域 | 气泡式布局，用户消息右对齐，AI 回复左对齐 |
| 输入框 | 底部固定，文字输入 + 发送按钮 |
| 打字机效果 | AI 回复逐字显示，模拟对话感 |
| 快捷问题 | 首屏显示 3-4 个常见问题入口（如"我 580 分能上什么学校？"） |
| AI 标识 | AI 消息旁标注"AI 生成" |
| 免责提示 | "AI 回答仅供参考，请以各省考试院公布信息为准" |

**智能体能力**：

| 能力 | 说明 | 示例 |
|------|------|------|
| 志愿填报咨询 | 根据分数/省份/选科推荐院校 | "河北物理类 580 分，推荐几所学校" |
| 专业/职业分析 | 分析专业前景、就业方向、薪资 | "计算机专业还值得报吗？" |
| 个性化追问 | 信息不足时主动追问 | "你是哪个省的？不同省分数线差得可大了" |
| 院校信息查询 | 查询特定学校信息 | "燕山大学怎么样？" |

**智能体人设**：

```
角色：张雪峰风格的高考志愿填报顾问

风格特征：
- 说话直接、接地气，不绕弯子
- 站在普通家庭角度考虑问题（就业、性价比、务实）
- 善于用类比和案例解释复杂概念
- 有明确的价值判断（什么专业好就业、什么学校性价比高）
- 敢于给出明确建议，不说正确的废话

回答规范：
1. 先给结论，再解释原因
2. 用具体数字说话（分数线、排名、就业率）
3. 信息不足时主动追问（一次只问一个关键问题）
4. 回答长度 200-500 字，简洁有力
5. 每次回答都要有可操作性

追问策略（信息收集优先级）：
1. 必须知道：省份、分数/位次、选科组合
2. 建议知道：家庭预算、兴趣方向、地域偏好
3. 深度了解：性格特点、考研/就业倾向、家庭资源
```

**对话引擎技术架构**：

```
用户提问
    │
    ▼
Dify Workflow（9 节点）
    │
    ├── 节点1: 接收消息
    ├── 节点2: LLM 信息提取（省份/分数/位次/科类/意图）
    ├── 节点3: 意图路由（志愿类/专业类/院校类/闲聊）
    ├── 节点4: 信息完整性检查
    ├── 节点5: 知识库检索（RAG）── 信息完整时
    ├── 节点6: 追问生成 ── 信息缺失时
    ├── 节点7: LLM 回答生成（结合人设+知识库+对话历史）
    ├── 节点8: 输出格式化
    └── 节点9: 返回用户
```

**知识库结构**：

| 知识库 | 内容 | 检索时机 |
|--------|------|---------|
| KB-1 张雪峰语料库 | 20+ Q&A 对，覆盖 4 种意图 | 每次对话 |
| KB-2 录取分数线 | 1-2 省份 × 3 年 × 200-400 所院校 | 志愿类 + 院校查询 |
| KB-3 专业百科 | 100-200 个热门专业 | 专业分析类 |
| KB-4 就业数据 | 各专业就业率/薪资/行业分布 | 专业分析 + 志愿填报 |

**边界行为**：

| 场景 | 期望行为 |
|------|---------|
| 用户要求"你帮我直接决定吧" | 拒绝代决定，引导用户自主选择 |
| 用户输入不可能的分数（如 750 分上清华） | 正常回答，不嘲讽 |
| 用户质疑"你说的和百度不一样" | 不争辩，建议以各省考试院官方信息为准 |
| 长时间对话（15+ 轮） | 保持风格一致性，不出现人设崩塌 |
| AI 无法确认的信息 | 诚实说"我不确定"，建议用户自行核实 |
| 网络异常 | 显示错误提示，支持重试 |

## 5. 非功能需求

### 5.1 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 推荐结果加载 | < 3 秒 | 含云函数查询 + 数据计算 |
| 首屏加载 | < 2 秒 | 小程序冷启动 |
| AI 首字输出 | 2-5 秒 | SSE 流式，用户感知即时响应 |
| 页面切换 | < 300ms | 无卡顿感 |

### 5.2 数据要求

| 维度 | MVP 范围 | 后续扩展 |
|------|---------|---------|
| 院校覆盖 | 约 1,000 所本科院校 | 全部本科+专科 |
| 省份覆盖 | 全部 31 省份（推荐算法） | 全部 |
| AI 知识库 | 1-2 个省份（河北 + 广东） | 全部省份 |
| 年份范围 | 近 3 年（2023-2025） | 近 5 年 |
| 专业覆盖 | 100-200 个热门专业 | 全部专业目录 |

### 5.3 安全与合规

| 要求 | 说明 | 实现方式 |
|------|------|---------|
| 内容安全检测 | 对用户输入和 AI 输出进行安全审核 | 微信 wx.msgSecCheck API |
| AI 内容标识 | 所有 AI 生成内容标注"AI 生成" | 对话页 UI 标识 |
| 免责声明 | 明确 AI 内容仅供参考 | 每次对话底部提示 |
| 算法备案 | 小程序上架需"深度合成"类目备案 | 企业主体 + 备案编号 |
| 用户隐私 | 不收集非必要个人信息 | 无需登录，数据本地存储 |

### 5.4 兼容性

- 支持微信最新版本及前 2 个大版本
- 适配不同屏幕尺寸（iPhone SE ~ iPad）
- 支持深色模式

### 5.5 可用性

- 无需登录即可使用全部功能
- 智能推荐：3 步获得结果（选省份 → 输分数 → 看推荐）
- AI 对话：1 步开始（点开即聊）

| 数据项 | 来源 | 格式 | 说明 |
|--------|------|------|------|
| 张雪峰语料 | B 站/抖音视频转文字，手动整理 | Markdown Q&A | 20+ 对，约 1-2 万字 |
| 录取分数线 | 同 6.1，精选 1-2 省份 | CSV | MVP 先覆盖河北 + 广东 |
| 专业百科 | 教育部专业目录 + 公开资料 | Markdown | 100-200 个热门专业 |
| 就业数据 | 麦可思《中国大学生就业报告》等 | Markdown | 按专业大类整理 |

## 7. 技术架构

### 7.1 整体架构

```
┌─────────────────────────────────────────────────────┐
│                   微信小程序（原生）                    │
│                                                      │
│  pages/home/        首页（三个入口）                    │
│  pages/recommend/   智能推荐 ←────────┐               │
│  pages/school/      院校详情          │ 微信云开发      │
│  pages/assess/      专业测评          │               │
│  pages/chat/        张雪峰咨询 ────────┼─ Dify API     │
└───────┬────────────────────────────┬──┘               │
        │                            │                  │
        ▼                            ▼                  │
┌───────────────┐          ┌──────────────────────┐    │
│  微信云开发    │          │   阿里云服务器 4C8G    │    │
│               │          │                      │    │
│  云函数       │          │  Dify 社区版 (Docker) │    │
│  云数据库     │          │  ├── Agent 对话       │    │
│               │          │  ├── Workflow 流程    │    │
│               │          │  └── 知识库 (RAG)     │    │
└───────────────┘          └──────────┬───────────┘    │
                                      │                │
                           ┌──────────▼──────────┐    │
                           │  LLM API（DeepSeek）  │    │
                           │  V3（主力）/ R1（推理）│    │
                           └─────────────────────┘    │
```

### 7.2 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 前端框架 | 微信原生小程序 | 性能最优，家长用户机型兼容性好 |
| 工具模块后端 | 微信云开发 | 零运维、天然集成微信生态 |
| AI 智能体引擎 | Dify 社区版（自部署） | 可视化编排 Workflow + 知识库管理 |
| 主力 LLM | DeepSeek-V3 | 中文口语化极强、成本极低（¥2/百万 token 输入） |
| 数据存储 | 微信云数据库（工具）+ Dify 知识库（AI） | 按模块分工 |
| 对话传输 | SSE 流式输出 | 用户 2-3 秒看到首字，体验流畅 |

### 7.3 并发容量

| 同时在线 | 体验 | 说明 |
|---------|------|------|
| 1-15 人 | 流畅 | 4C8G 服务器所有请求立即处理 |
| 15-30 人 | 轻微延迟 | 部分排队，3-8 秒出首字 |
| 30-50 人 | 可感知延迟 | 排队较长，5-15 秒出首字 |
| 50+ 人 | 需要优化 | 需排队提示或弹性扩容 |

> 实际缓解因素：对话有天然错峰（用户读回答需 10-30 秒），100 人在线实际同时"等回复"的约 20-30 人。

## 8. 用户故事与验收标准

### 8.1 智能推荐

| US-02 | 作为考生，我可以输入全省位次获得更精准的推荐 | 当位次填写时，推荐算法以位次为优先排序依据 |
| US-03 | 作为考生，我可以在推荐列表中查看每所院校的历年录取分数线 | 每个院校卡片显示近 3 年最低分和最低位次 |
| US-04 | 作为考生，我可以点击院校查看详细信息 | 详情页展示院校介绍、排名、专业组及各专业历年分数线 |
| US-05 | 作为考生，我可以看到新高考的专业组及选科要求 | 新高考省份推荐精确到专业组，展示选科要求 |
| US-06 | 作为家长，我可以通过院校排名快速判断学校实力 | 院校卡片和详情页均展示排名信息 |

| ID | 用户故事 | 验收标准 |
|----|---------|---------|
| US-07 | 作为考生，我可以通过 MBTI 测试了解自己的性格类型 | 完成约 20 题 MBTI 测试，返回四维度结果及性格类型解读 |
| US-08 | 作为考生，我可以通过职业兴趣测试了解适合的专业方向 | 完成约 20 题 Holland 测试，返回推荐的 3-5 个专业方向 |
| US-09 | 作为考生，我可以从测评结果直接查看匹配的院校 | 结果页提供"查看匹配院校"按钮，跳转推荐页 |
| US-10 | 作为考生，我可以随时退出测评并保存进度 | 支持中断后继续答题，进度存储在本地 |

### 8.3 张雪峰咨询（AI 智能体）

| ID | 用户故事 | 验收标准 |
|----|---------|---------|
| US-11 | 作为考生，我可以直接问"580 分能上什么学校"并获得建议 | AI 在 2-5 秒内开始回复，给出具体院校推荐 |
| US-12 | 作为考生，当我没提供省份时 AI 会主动追问 | AI 自然地追问关键缺失信息，一次只问一个 |

| US-14 | 作为考生，AI 的回答风格像张雪峰——直接、接地气、有态度 | AI 不说正确的废话，给出明确建议 |

## 11. 成本模型

### 11.1 单用户 LLM 成本

```
一次完整使用 = 15 轮对话
对话：15 轮 × ~8,000 tokens/轮 = 120,000 tokens
  输入成本 ≈ ¥0.24（DeepSeek-V3 ¥2/百万 token）
  输出成本 ≈ ¥0.06
  单用户总成本 ≈ ¥0.36
```

### 11.2 月度运营成本

| 月活用户 | LLM 月费 | 服务器月费 | 数据 API | 合计 |
|---------|---------|-----------|---------|------|
| 500 | ¥180 | ¥300 | ¥1,000 | **¥1,480** |
| 2,000 | ¥720 | ¥300 | ¥2,000 | **¥3,020** |
| 5,000 | ¥1,800 | ¥300 | ¥3,000 | **¥5,100** |

### 11.3 成本速算

```
月总成本 ≈ 月活用户 × ¥0.36 + ¥300（服务器）+ ¥1,000-3,000（数据）
```

## 13. 风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| 第三方数据 API 质量差或价格变 | 中 | 高 | MVP 先用最小数据集，同步准备备用数据源 |
| DeepSeek 风格模拟不理想 | 中 | 中 | 多轮提示词调优 + 充实张雪峰语料库 |
| 4C8G 服务器扛不住并发 | 低 | 高 | 流式输出缓解体验 + 准备弹性扩容方案 |
| 小程序审核不通过（AI 对话类需备案） | 中 | 高 | 需企业主体 + 算法备案，所有 AI 输出标注"AI 生成"，实现内容安全检测 |
| LLM 幻觉（编造学校/分数） | 中 | 高 | 知识库约束 + Prompt 明确禁止 + 关键数据加校验；2025 年已有首例 AI 幻觉侵权案 |
| 大厂免费产品挤压空间 | 高 | 中 | 差异化在"有态度的深度建议"而非"数据工具" |
