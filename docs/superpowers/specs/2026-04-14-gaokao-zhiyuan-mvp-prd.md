## 1. 产品概述

### 1.1 产品背景

2025 年高考报名人数 **1,335 万**，志愿填报付费市场规模 **10.9 亿元**（艾媒咨询）。88.1% 的高考生愿意付费获取志愿填报服务，但市场存在严重的信息不对称和服务分层：

- **大厂免费工具**（夸克/百度/腾讯）：数据齐全但推荐中立、模板化，缺乏个性化深度
- **人工咨询**（张雪峰/峰学蔚来 12,999-18,999 元）：有态度、有深度，但价格昂贵且名额稀缺
- **市场空白**：缺少"有态度的 AI + 低价普惠"的中间档产品

同时，2025 年新京报实测 10 款 AI 志愿产品发现，头部大厂产品普遍存在位次定位失误、选科限制忽视、推荐已撤销专业等严重问题，用户对"靠谱的 AI 志愿工具"有强烈需求。

### 1.2 产品定位

**一句话定位**：张雪峰风格的 AI 志愿填报助手 — 工具查数据，智能体给建议。

**定位公式**：

```
大厂产品 = 数据工具（冷冰冰、中立、标准化）
张雪峰本人 = 万元咨询（有态度、深度、但贵且稀缺）
我们 = 张雪峰风格的 AI（有态度 + 深度追问 + 低价普惠）
```

### 1.3 产品形态

微信小程序，包含四大板块：

```
高考志愿填报助手（微信小程序）
├── 数据爬取与深度研究（后端）  ← AI 驱动批量研究
│   ├── 840 条专业深度报告（独立文件）
│   ├── 全国高等学校院校报告（独立文件）
│   └── 综合报告数据源
│
├── 高考咨询智能体（免费）  ← Dify 驱动
│   └── 张雪峰风格 AI 对话
│
├── 测评填表（免费）  ← 微信云开发
│   ├── MBTI 性格测试
│   ├── 个人信息完善（省份/分数/选科）
│   └── APSET 职业专业选择测试
│
└── 测评结果预览与下载  ← 微信云开发
    ├── MBTI 测试结果（免费）
    ├── 职业测试结果（免费）
    └── 综合报告（付费） ← 结合测评 + 专业/院校研究数据
```

### 免费/付费分层

| 功能 | 免费体验 | 付费解锁 |
|------|---------|---------|
| 高考咨询智能体 | ✅ 无限次对话 | - |

### 1.4 产品目标

| 目标 | 衡量指标 | MVP 目标值 |
|------|---------|-----------|
| 降低信息门槛 | 推荐结果加载时间 | < 3 秒 |
| 提供有态度的建议 | 对话完成率（15 轮） | > 60% |
| 数据可靠性 | 幻觉率（编造数据） | < 5% |
| 用户满意度 | "有用"评分 4 分以上占比 | > 70% |
| 专业研究覆盖 | 深度研究完成专业数 | ≥ 840 条 |
| 商业验证 | 综合报告付费转化率 | > 10% |

## 2. 目标用户

### 2.1 用户画像

#### 用户 A：高考生

| 维度 | 描述 |
|------|------|
| 年龄 | 17-19 岁 |
| 场景 | 高考出分后需要快速了解能上什么学校、什么专业适合自己 |
| 信息渠道 | 抖音/B 站/小红书/知乎 |
| AI 接受度 | 高，愿意尝试 AI 工具 |
| 决策权 | 约 50%（另一半家长主导） |
| 付费能力 | 有限，可接受百元级消费 |
| 核心诉求 | "告诉我能上什么学校" + "什么专业适合我" |

#### 用户 B：家长

| 维度 | 描述 |
|------|------|
| 年龄 | 40-50 岁 |
| 场景 | 帮孩子选志愿，怕选错影响一生 |
| 信息渠道 | 微信/短视频/朋友推荐 |
| AI 接受度 | 中等，认为"AI 不够靠谱"，更信任有态度的专家 |
| 决策权 | 约 50%（另一半孩子自主） |
| 付费意愿 | 平均 3,000-5,000 元，部分可达万元 |
| 核心诉求 | "别选错" + "性价比高的学校" + "好就业的专业" |

### 2.2 用户痛点排序

| 排名 | 痛点 | 现有解决方案 | 未满足的原因 |
|------|------|------------|------------|
| 1 | AI 推荐结果不可靠/不一致 | 大厂免费工具 | 新京报实测：同一条件输入不同产品，9 所推荐院校仅 2 所重合 |
| 2 | 缺乏个性化深度建议 | 大厂 AI 志愿助手 | 回答中立模板化，不敢给明确建议 |
| 3 | 高价咨询不透明/买不起 | 张雪峰/峰学蔚来 | 12,999-18,999 元，预约排到 2026 年 |
| 4 | 选择焦虑（选项太多） | 各种工具 | 工具反而加剧了焦虑（30-112 个志愿选项） |
| 5 | 信息不对称 | 掌上高考/阳光志愿 | 数据有，但理解门槛高 |

### 4.1 首页

**功能描述**：展示三个功能入口，用户可快速进入任一模块。

**页面元素**：

| 元素 | 说明 | 交互 |
|------|------|------|
| 产品标题/Logo | "高考志愿填报助手" | - |
| 高考咨询智能体入口 | 卡片式入口，AI 头像 + "免费"标签 | 点击跳转对话页 |
| 测评填表入口 | 卡片式入口，图标+文字 | 点击跳转测评首页（MBTI/个人信息/APSET） |
| 测评结果入口 | 卡片式入口，显示已完成状态 | 点击跳转结果页（含综合报告入口） |
| 免责声明 | "数据仅供参考，请以各省考试院公布为准" | 底部固定 |

**设计要求**：简洁清晰，三个入口一目了然。智能体入口突出"免费 AI 咨询"标签，测评结果入口引导用户发现综合报告。

### 4.2 数据爬取与深度研究（后端模块）

**功能描述**：通过 AI 驱动的深度研究流程，对中国高等学校和专业进行批量深度研究，生成独立报告。这些报告是综合报告的核心数据来源，也是智能体知识库的重要组成部分。

**研究范围**：

| 研究对象 | 数量 | 报告内容 |
|---------|------|---------|
| 本科专业 | ~840 条 | 专业概述、核心课程、就业前景、薪资数据、院校推荐、适合人群 |
| 高等学校 | ~1,000+ 所 | 院校概况、优势专业、历年分数线、排名、就业数据 |

**单条专业报告结构**：

```
## [专业名称]（[专业代码]）
- 所属门类 / 学科类
- 培养目标与核心课程
- 就业前景与薪资范围（应届/3年/5年）
- 主要就业行业与岗位
- 推荐院校（按梯队）
- 适合人群特征（性格/能力/兴趣）
- 考研方向与深造建议
- 张雪峰风格点评（务实、接地气）
```

**数据用途**：

| 用途 | 说明 |
|------|------|
| 综合报告生成 | 结合用户测评数据 + 专业研究数据，生成个性化综合报告 |
| 智能体知识库 | 导入 Dify 知识库（KB-3 专业百科），提升回答深度 |
| 院校推荐参考 | 作为推荐算法的补充数据源 |

**执行方式**：通过 AI 深度研究工具（如 Tavily Research）批量生成，平均每天完成 120 条，W2 内完成全部 840 条。

### 4.3 测评填表

#### 4.3.1 MBTI 性格测试

**功能描述**：通过 MBTI 简化版测试帮助考生了解性格类型。

| 测试项 | 说明 |
|--------|------|
| 题数 | ~20 题 |
| 维度 | E/I, S/N, T/F, J/P |
| 输出 | 4 字母类型（如 INTJ）+ 性格解读 |
| 交互 | 每题 2 选项，选择后自动进入下一题，支持本地缓存进度 |

#### 4.3.2 个人信息完善

**功能描述**：采集用户基本信息，为综合报告和智能体推荐提供个性化数据。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 高考省份 | 下拉选择 | 是 | 31 个省份 |
| 高考分数 | 数字输入 | 是 | 0-750 整数 |
| 全省位次 | 数字输入 | 否 | 填写位次推荐更精准 |
| 科类 | 下拉选择 | 是 | 根据省份自动适配 |
| 选科组合 | 多选 | 新高考必填 | 物/化/生/政/史/地 |
| 家庭预算 | 单选 | 否 | 公办优先/民办可接受/不限 |
| 地域偏好 | 多选 | 否 | 省内/省外/特定区域 |
| 考研/就业倾向 | 单选 | 否 | 考研优先/就业优先/ undecided |

#### 4.3.3 APSET 职业专业选择测试

**功能描述**：结合职业兴趣和学科能力，推荐适合的专业方向。

| 测试项 | 说明 |
|--------|------|
| 题数 | ~20 题 |
| 维度 | 职业兴趣（Holland RIASEC）+ 学科偏好 + 能力自评 |
| 输出 | 推荐 3-5 个专业大类 + 匹配度排序 + 推荐理由 |
| 交互 | 题目形式多样化（单选/多选/排序），支持中断续答 |

#### 4.4.3 综合报告（付费）

**功能描述**：结合用户测评数据（MBTI + 个人信息 + APSET）和专业/院校深度研究数据，生成个性化综合报告。这是产品的核心付费价值。

**报告结构**：

```
## 高考志愿填报综合报告

### 1. 个人画像
- 性格特征（基于 MBTI）
- 兴趣与能力（基于 APSET）
- 核心条件（分数/位次/省份/选科）

### 2. 专业推荐分析
- 3-5 个推荐专业，每个包含：
  - 专业深度研究报告摘要
  - 与个人画像的匹配分析
  - 就业前景与薪资预期
  - 推荐院校梯队

### 3. 院校推荐方案
- 冲/稳/保三档院校列表
- 每所院校的匹配理由
- 历年录取数据分析

### 4. 张雪峰风格点评
- 针对用户具体情况的务实建议
- 需要避开的"坑"
- 性价比分析

### 5. 行动建议
- 志愿填报优先级排序
- 需要进一步了解的信息
```

**付费模式**：

| 层级 | 内容 | 价格 |
|------|------|------|
| 免费预览 | 个人画像 + 1 个推荐专业摘要 | 免费 |
| 完整报告 | 全部 5 个章节完整内容 | ¥50-100 |

### 4.5 高考咨询智能体（免费）

#### 4.4.1 对话页

**功能描述**：用户以自然语言与 AI 智能体对话，获取张雪峰风格的志愿填报建议。

**页面结构**：

| 元素 | 说明 |
|------|------|
| 对话区域 | 气泡式布局，用户消息右对齐，AI 回复左对齐 |
| 输入框 | 底部固定，文字输入 + 发送按钮 |
| 打字机效果 | AI 回复逐字显示，模拟对话感 |
| 快捷问题 | 首屏显示 3-4 个常见问题入口（如"我 580 分能上什么学校？"） |
| AI 标识 | AI 消息旁标注"AI 生成" |
| 免责提示 | "AI 回答仅供参考，请以各省考试院公布信息为准" |

**智能体能力**：

| 能力 | 说明 | 示例 |
|------|:----:|------|
| 志愿填报咨询 | 根据分数/省份/选科推荐院校 | "河北物理类 580 分，推荐几所学校" |
| 专业/职业分析 | 分析专业前景、就业方向、薪资 | "计算机专业还值得报吗？" |
| 个性化追问 | 信息不足时主动追问 | "你是哪个省的？不同省分数线差得可大了" |
| 院校信息查询 | 查询特定学校信息 | "燕山大学怎么样？" |

**智能体人设**：

```
角色：张雪峰风格的高考志愿填报顾问

风格特征：
- 说话直接、接地气，不绕弯子
- 站在普通家庭角度考虑问题（就业、性价比、务实）
- 善于用类比和案例解释复杂概念
- 有明确的价值判断（什么专业好就业、什么学校性价比高）
- 敢于给出明确建议，不说正确的废话

回答规范：
1. 先给结论，再解释原因
2. 用具体数字说话（分数线、排名、就业率）
3. 信息不足时主动追问（一次只问一个关键问题）
4. 回答长度 200-500 字，简洁有力
5. 每次回答都要有可操作性

追问策略（信息收集优先级）：
1. 必须知道：省份、分数/位次、选科组合
2. 建议知道：家庭预算、兴趣方向、地域偏好
3. 深度了解：性格特点、考研/就业倾向、家庭资源
```

**对话引擎技术架构**：

```
用户提问
    │
    ▼
Dify Workflow（9 节点）
    │
    ├── 节点1: 接收消息
    ├── 节点2: LLM 信息提取（省份/分数/位次/科类/意图）
    ├── 节点3: 意图路由（志愿类/专业类/院校类/闲聊）
    ├── 节点4: 信息完整性检查
    ├── 节点5: 知识库检索（RAG）── 信息完整时
    ├── 节点6: 追问生成 ── 信息缺失时
    ├── 节点7: LLM 回答生成（结合人设+知识库+对话历史）
    ├── 节点8: 输出格式化
    └── 节点9: 返回用户
```

**知识库结构**：

| 知识库 | 内容 | 检索时机 |
|--------|------|---------|
| KB-1 张雪峰语料库 | 20+ Q&A 对，覆盖 4 种意图 | 每次对话 |
| KB-2 录取分数线 | 1-2 省份 × 3 年 × 200-400 所院校 | 志愿类 + 院校查询 |
| KB-3 专业深度研究 | 840 条专业独立报告（来自深度研究模块） | 专业分析类 |
| KB-4 院校深度研究 | 院校独立报告 + 就业数据 | 院校查询 + 专业分析 |

**边界行为**：

| 场景 | 期望行为 |
|------|---------|
| 用户要求"你帮我直接决定吧" | 拒绝代决定，引导用户自主选择 |
| 用户输入不可能的分数（如 750 分上清华） | 正常回答，不嘲讽 |
| 用户质疑"你说的和百度不一样" | 不争辩，建议以各省考试院官方信息为准 |
| 长时间对话（15+ 轮） | 保持风格一致性，不出现人设崩塌 |
| AI 无法确认的信息 | 诚实说"我不确定"，建议用户自行核实 |
| 网络异常 | 显示错误提示，支持重试 |

## 7. 技术架构

### 7.1 整体架构

```
┌─────────────────────────────────────────────────────┐
│                   微信小程序（原生）                    │
│                                                      │
│  pages/home/        首页（三个入口）                    │
│  pages/chat/        高考咨询智能体 ──────── Dify API   │
│  pages/assess/      测评填表 ───────────── 微信云开发  │
│  pages/result/      测评结果 ───────────── 微信云开发  │
│  pages/report/      综合报告（付费）────── 微信云开发   │
└───────┬────────────────────────────┬──┘               │
        │                            │                  │
        ▼                            ▼                  │
┌───────────────┐          ┌──────────────────────┐    │
│  微信云开发    │          │   阿里云服务器 4C8G    │    │
│               │          │                      │    │
│  云函数       │          │  Dify 社区版 (Docker) │    │
│  云数据库     │          │  ├── Agent 对话       │    │
│               │          │  ├── Workflow 流程    │    │
│               │          │  └── 知识库 (RAG)     │    │
└───────────────┘          └──────────┬───────────┘    │
                                      │                │
                           ┌──────────▼──────────┐    │
                           │  LLM API（DeepSeek）  │    │
                           │  V3（主力）/ R1（推理）│    │
                           └─────────────────────┘    │
                                      │                │
                           ┌──────────▼──────────┐    │
                           │  数据爬取与深度研究    │    │
                           │  840 条专业独立报告    │    │
                           │  院校独立报告         │    │
                           │  → 知识库 + 综合报告   │    │
                           └─────────────────────┘    │
```

### 7.2 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 前端框架 | 微信原生小程序 | 性能最优，家长用户机型兼容性好 |
| 工具模块后端 | 微信云开发 | 零运维、天然集成微信生态 |
| AI 智能体引擎 | Dify 社区版（自部署） | 可视化编排 Workflow + 知识库管理 |
| 主力 LLM | DeepSeek-V3 | 中文口语化极强、成本极低（¥2/百万 token 输入） |
| 数据存储 | 微信云数据库（工具）+ Dify 知识库（AI） | 按模块分工 |
| 对话传输 | SSE 流式输出 | 用户 2-3 秒看到首字，体验流畅 |

### 7.3 并发容量

| 同时在线 | 体验 | 说明 |
|---------|------|------|
| 1-15 人 | 流畅 | 4C8G 服务器所有请求立即处理 |
| 15-30 人 | 轻微延迟 | 部分排队，3-8 秒出首字 |
| 30-50 人 | 可感知延迟 | 排队较长，5-15 秒出首字 |
| 50+ 人 | 需要优化 | 需排队提示或弹性扩容 |

> 实际缓解因素：对话有天然错峰（用户读回答需 10-30 秒），100 人在线实际同时"等回复"的约 20-30 人。

## 11. 成本模型

### 11.1 单用户 LLM 成本

```
一次完整使用 = 15 轮对话
对话：15 轮 × ~8,000 tokens/轮 = 120,000 tokens
  输入成本 ≈ ¥0.24（DeepSeek-V3 ¥2/百万 token）
  输出成本 ≈ ¥0.06
  单用户总成本 ≈ ¥0.36
```

### 11.2 月度运营成本

| 月活用户 | LLM 月费 | 服务器月费 | 数据 API | 合计 |
|---------|---------|-----------|---------|------|
| 500 | ¥180 | ¥300 | ¥1,000 | **¥1,480** |
| 2,000 | ¥720 | ¥300 | ¥2,000 | **¥3,020** |
| 5,000 | ¥1,800 | ¥300 | ¥3,000 | **¥5,100** |

### 11.3 成本速算

```
月总成本 ≈ 月活用户 × ¥0.36 + ¥300（服务器）+ ¥1,000-3,000（数据）
```
