> 排期：Week 3（04/28 - 05/02）
> 前置依赖：Phase 2.3 Prompt 调优、Phase 3.1 知识库补全
> 阻塞任务：Phase 4.1 意图识别

## 1. 如何完成

### 核心问题

当前 Agent 的多轮对话存在以下不足：
1. 用户说"我河北的"后，Agent 需要记住省份，后续不再重复追问
2. 信息收集需要自然的对话流程，而非机械式一问一答
3. 用户中途换话题时，需要灵活切换上下文

### 优化方案

#### 方案 A：纯 Prompt 优化（推荐，简单有效）

在 System Prompt 中增加"信息收集状态管理"指令：

```
## 对话信息管理
你会通过对话逐步收集以下信息，收集到后记住并在后续回答中使用：
- 省份：收集到后不再追问
- 分数/位次：收集到后不再追问
- 选科（物理类/历史类）：收集到后不再追问

信息收集优先级：省份 > 选科 > 分数/位次
每次回答时，先基于已收集到的信息给出尽可能有用的建议，再追问缺失信息。
不要一次性追问所有信息，每次最多追问一个关键问题。
```

#### 方案 B：Dify 变量 + 条件分支（复杂，效果更好）

在 Chatflow 中添加变量节点：
1. 开始节点后添加"变量赋值"节点
2. 用 LLM 从对话中提取结构化信息（省份/分数/选科）
3. 根据已有信息走不同分支（信息不全 → 追问 / 信息齐全 → 给建议）

### 推荐路线

先用方案 A 快速见效，如果效果不够再加方案 B。

### 测试场景

设计 5 个多轮对话测试用例：

1. 渐进式信息收集：
   - "你好" → "河北" → "物理类" → "580分" → 应该越来越精准

2. 跨话题对话：
   - "计算机怎么样" → "那电气工程呢" → 应该对比两个专业而非独立回答

3. 信息补充：
   - "我580分能上什么学校" → "哦我是广东的" → 应该基于广东重新给建议

4. 上下文引用：
   - "武汉大学怎么样" → "那它和华中科技大学比呢" → 应该理解"它"指武汉大学

5. 中途换题：
   - "河北物理类580" → "对了，考研和就业哪个好" → 回答后应能继续志愿话题
