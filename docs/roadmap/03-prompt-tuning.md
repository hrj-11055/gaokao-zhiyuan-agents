# Phase 2.3 — Prompt 第一轮调优

> 排期：Week 1-2（04/18 - 04/22）
> 前置依赖：Phase 2.1 测试报告完成
> 阻塞任务：Phase 3.2 多轮对话优化、Phase 3.3 安全护栏

---

## 1. 如何完成

### 调优流程

```
分析测试报告 → 定位问题分类 → 修改 Prompt → 重新发布 → 二次验证
```

### 按问题类型对应调优策略

| 问题类型 | Prompt 修改方向 | 修改位置 |
|---------|----------------|---------|
| A — 缺少追问 | 强化追问策略部分，加"在以下信息缺失时必须追问" | 追问策略章节 |
| B — 回答太泛 | 加"禁止使用模糊表述，每次必须给出至少 2 个具体学校或专业名" | 回答规范章节 |
| C — 编造数据 | 加"如果知识库中没有该数据，明确告诉用户'我手头没有这个数据'" | 禁止行为章节 |
| D — 风格不符 | 增加更多张雪峰风格示例，强化语气描述 | 回答风格示例章节 |
| E — 长度不当 | 调整 max_tokens 或在 prompt 中加长度约束 | 回答规范 + 模型参数 |
| F — 知识库未命中 | 调整知识检索参数（Top K、阈值）或优化 prompt 中的引用指令 | 知识检索节点 + prompt |

### 具体操作

1. 汇总测试报告中的问题，按 A-F 分类统计
2. 针对最集中的 2-3 个问题类型，修改 prompt
3. 通过 Dify API 更新 LLM 节点的 prompt 字段
4. 重新发布 Chatflow
5. 用问题最严重的 5 道题重新测试，确认改善

### Prompt 修改方式

```bash
# 通过 API 更新（推荐，可版本控制）
# 在本机执行 python 脚本更新 prompt
```

或直接在 Dify UI 中编辑 LLM 节点 → 修改 System Prompt → 发布

## 2. 验收标准

- [ ] 测试报告中的主要问题已定位并分类
- [ ] Prompt 已针对性修改（至少覆盖最严重的 2 个问题类型）
- [ ] 修改后对原问题最严重的 5 道题重新测试，至少 4 题改善
- [ ] Chatflow 已重新发布
- [ ] 修改记录已写入文档（改了什么、为什么改）
