# Phase 4.1 — 意图识别与多分支路由

> 排期：Week 4（05/05 - 05/09）
> 前置依赖：Phase 3.2 多轮对话优化
> 阻塞任务：无（可与 Phase 4.2 并行）

---

## 1. 如何完成

### 背景

当前所有用户输入都走同一条链路：知识检索 → LLM → 回复。
但实际上用户有不同类型的意图，可以走不同的处理分支来提升效果。

### 意图分类

| 意图 | 示例 | 处理方式 |
|------|------|---------|
| 查分数线 | "武汉大学河北2024分数线" | 知识检索 → LLM |
| 问专业 | "计算机专业就业怎么样" | 知识检索（KB-3 为主） → LLM |
| 问学校 | "燕山大学和河北工业大学哪个好" | 知识检索（KB-4 为主） → LLM |
| 求推荐 | "580分河北物理类能报什么" | 知识检索（KB-2 为主） → LLM |
| 闲聊/打招呼 | "你好""你是谁" | 跳过知识检索，直接 LLM |

### Dify 实现方案

在 Chatflow 中添加一个 LLM 分类节点：

```
用户输入 → LLM(意图分类) → 条件分支
                              ├── 查分数线 → 知识检索(KB-2) → LLM(回答)
                              ├── 问专业   → 知识检索(KB-3) → LLM(回答)
                              ├── 问学校   → 知识检索(KB-4) → LLM(回答)
                              ├── 求推荐   → 知识检索(全部)  → LLM(回答)
                              └── 闲聊     → LLM(回答)
```

### 意图分类 Prompt

```
你是一个意图分类器。根据用户输入，判断意图类型。
只输出以下类别之一：
- score_query：查分数线
- major_query：问专业
- school_query：问学校
- recommendation：求推荐（分数+选科+省份齐全）
- chat：闲聊/打招呼/其他

用户输入：{{query}}
意图类型：
```

### 实施步骤

1. 在 Dify Chatflow 中添加 LLM 分类节点
2. 添加 IF/ELSE 条件分支节点
3. 每个分支配置不同的知识检索目标
4. 汇聚到一个通用 LLM 回答节点
5. 测试不同意图的路由准确性

---

## 2. 验收标准

- [ ] 意图分类准确率 ≥ 90%（测试 20 条不同意图的输入）
- [ ] 不同意图走到正确的知识检索分支
- [ ] 闲聊类直接回答，不浪费知识检索资源
- [ ] Chatflow 无死循环或断路
- [ ] 平均响应时间不超过当前方案的 1.5 倍
